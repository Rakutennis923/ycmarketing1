# 太平洋房屋友成幸福團隊｜業績行動看板

**交付狀態：程式已完成，尚未部署或連接正式 Google 資料。**

預設門店為「友成南平店」。支援手機與電腦，每位夥伴每月一張圖卡。業績單位為**萬元**。原問卷保留，新網頁使用同一份 Google 試算表的獨立分頁。

## 先看效果

下載並解壓縮後，直接以 Chrome、Edge 或 Safari 開啟 `preview.html`，用上方「統計年度／月份」切換各月資料。也可以將此檔單獨下載開啟。

預覽已載入南平店 23 位人事名單，但不預填任何虛構業績。可測試人事管理、輸入月報、切換月份與搜尋；重新整理即重設。預覽不會送出原 Google 問卷，也不會寫入正式試算表。

- 主標題：太平洋房屋友成幸福團隊／友成南平店；已依附件移除重複品牌列與「年／月 業績行動看板」列。

- 月報以固定人員識別碼連結；改名後舊月份會顯示新姓名，但歷史業績不會遺失。離職只停用新月份輸入，不刪除舊資料。
- 以獨立的「統計年度」與「月份」下拉選單輸入和查看資料，支援 2000～2099 年；切換月份即讀取該月統計。
- 每月早會可更新當下廣告、庫存與業績；下個月重新輸入，舊月份完整保留。
- 本店總目標標示為「南平店本月業績目標」（其他門店會依店名切換）。本月目標以紅色強調；達成率滿 60%、70%、80%、90%、100% 時更換鼓勵話。
- 超過 100% 顯示實際百分比；目標為 0 時顯示「—」，不出現除零錯誤。
- 10 句金句，依 Asia/Taipei 每週一午夜換句，10 週循環。
- 各門店分開登入、讀寫隔離；門店選項由管理者設定，未虛構其他店名。
- 每 15 秒輪詢；隱藏分頁暫停，返回分頁或恢復網路時更新。
- 開啟編輯視窗即暫停畫面同步，也忽略編輯前已送出、編輯中才返回的舊回應。
- 草稿保留在該分頁 sessionStorage；儲存成功才刪除，關閉分頁或瀏覽器可能失去草稿。
- 同筆資料修改以版本摘要檢查衝突，顯示「雲端最新／您的輸入」比對；不自動覆蓋。
- 儲存失敗保留輸入；逾時後重送同一請求不重複新增。
- 新月份獨立保存，保留歷史月份。

## 資料流與原問卷的關係

GitHub Pages 提供網站入口；頁內嵌入 Google Apps Script 看板。看板透過 `google.script.run` 讀寫 Google Sheets，因此不需跨網域 `fetch` 或不能確認結果的 `no-cors` 寫入。

執行初始化會在指定試算表新增：

| 分頁 | 用途 |
|---|---|
| 業績圖卡_v1 | 每店、每月、每位夥伴的最新資料 |
| 人事資料_v1 | 人員姓名、職務、在職／離職狀態及版本 |
| 廣告平台_v1 | 下拉選單選項 |

**不修改、刪除或搬動原本的「表單回應」分頁。** 原 Google 表單送出的新回應仍依原表單設定寫入原回應表，**不會自動轉入新圖卡**；新網頁也不會建立 Google Forms 回應。若需要舊回應移轉或原表單持續雙入口填寫，須先確認回應表與門店、人員、月份的對應規則再增加匯入流程。

使用者提供的試算表標題含「回應的副本」，目前未確認它就是原表單的即時回應目的地。本版直接將它作為新網頁的儲存來源，不假定它與原問卷連結。

同一門店、月份、人員識別碼為同一筆記錄。姓名可由「人事管理」修改，固定識別碼會維持歷史連結；同名的在職人員會被阻擋，避免誤建。年度目標是該月份的年度目標快照，不會自動修改其他月份的快照。

初始化名單：龔泰禧（主管）、黃國興、廖茂宏、陳洋弘、魏汝殷、陳彥華、杜杰陽、范瑞洪、林湘縈、詹明軒、陳芮慈、曾鈺傑、葉志傑、林煥為、卓正得、董凱元、古郁潔、何百玲、劉淑燕、李明憲(阿達)、林佩蓉、湯雅玲、劉健安。除龔泰禧外預設職務為「業務」，可在畫面修改。

## 一次性部署：Google Apps Script

1. 使用具有編輯權限的 Google 帳號開啟本次提供的試算表，選「擴充功能 → Apps Script」。
2. 將 `backend/Code.gs` 貼入指令碼編輯器。
3. 新增 HTML 檔，命名為 **App**，貼入 `backend/App.html` 全部內容。
4. 在專案設定開啟 `appsscript.json` 顯示，套用 `backend/appsscript.json` 內容；時區為 Asia/Taipei。
5. 在「專案設定 → 指令碼屬性」增加三個屬性：

| 屬性 | 設定值 |
|---|---|
| SPREADSHEET_ID | 本次提供的 Google 試算表網址中 `/d/` 與 `/edit` 之間的文字 |
| GITHUB_ORIGIN | `https://rakutennis923.github.io`（不能加尾端斜線或儲存庫路徑；換帳號時跟著調整） |
| STORE_CODES_JSON | 各店名稱與通行碼的 JSON 對照，例如 `{"友成南平店":"自行設定至少12字元的通行碼"}`；請使用隨機長碼，不要使用範例字串 |

6. 在 Apps Script 編輯器執行 **setup_**，依 Google 畫面完成試算表權限授權。初始化可重複執行，不會覆蓋既有內容。請勿將通行碼貼到聊天或公開 GitHub。
7. 「部署 → 新增部署 → 網頁應用程式」：執行身分選管理者本人。若要讓夥伴不登入 Google 即可使用，存取對象需要允許任何人開啟應用程式，但每筆讀寫仍受本程式門店通行碼驗證。請由管理者確認這項設定；受 Workspace 政策限制時須調整部署策略。
8. 複製以 `/exec` 結尾的部署網址，填到 GitHub 專案 `config.js` 的 `appUrl`。

部署 URL 可公開，但通行碼及 session 不可公開。直接開啟 Apps Script 網址會要求回到 GitHub 頁面，這是嵌入來源檢查機制。

**既有試算表目前可透過連結匿名讀取。若業績資料不應對外公開，請管理者在加入正式資料前，將試算表分享改成僅指定人員。** 使用本系統不需要將試算表公開發布到網路。網頁應用程式的開啟權限，與試算表本身的分享權限是不同設定。

## 一次性部署：GitHub Pages

建議建立獨立儲存庫 **ycmarketing1**，避免與既有房仲提示詞產生器混在一起。

1. 建立儲存庫並上傳本資料夾內容。`index.html` 必須在儲存庫根目錄，不要再包一層資料夾。
2. `config.js` 填入 Apps Script 的 `/exec` 網址。
3. Settings → Pages → Build and deployment → Deploy from a branch。
4. 分支選 `main`，資料夾選 `/ (root)`，儲存。
5. 等待 Pages 顯示部署完成後，從 GitHub 提供的實際網址開啟；不要把示範預覽網址當正式看板。
6. 使用各店通行碼登入。通行碼只填入 Apps Script 指令碼屬性及網頁登入畫面，不提交到 GitHub。

GitHub Pages 是否可從私有儲存庫發布取決於帳號方案。若使用公開儲存庫，此程式包只包含程式與示範資料，沒有真實人員、業績、通行碼或試算表 ID。

## 增加門店與調整平台

- 增加門店：在 `STORE_CODES_JSON` 增加一個真實店名與不同的隨機通行碼。登入後頁首與資料自動切換。
- 改通行碼：更新指令碼屬性即可，舊通行碼建立的 session 會失效。
- 平台清單：編輯「廣告平台_v1」A 欄；不要刪除標題列。「其他網路平台」這個選項文字需保持一致，才能顯示額外名稱欄。
- Apps Script 程式改版後，要到「管理部署」編輯既有部署、選新版本，才能讓 `/exec` 使用新程式。
- GitHub 頁面變更後等候 Pages 發布，必要時重新整理。

## 同步與權限的實際界線

- 15 秒為畫面開啟時的輪詢週期，不是 WebSocket 即時推播；網路、Google 配額與伺服器忙碌可能延遲。
- 暫停同步僅保護正在編輯的裝置，不鎖住全店。不同夥伴可同時填寫；同一筆則要求比對版本。
- 門店通行碼為簡易團隊存取控制；知道該店通行碼的人可讀寫該店全部圖卡，未提供個人帳號與僅能修改自己的限制。不要將它視為企業級身分驗證；大量對外或更敏感用途應升級個人登入與稽核。
- session 最長 6 小時，Google 快取也可能較早失效。編輯中失效時可重新登入並保留草稿。
- Apps Script 鎖可避免網頁寫入彼此衝突，無法鎖住人員直接修改 Sheets 的動作。平常請透過看板修改，不要在同時填報期間直接更動資料分頁。
- 尚未匯入原問卷歷史資料；沒有真實資料出現在預覽。

4. 模擬斷線儲存，確認有錯誤提示且草稿未消失；重試不重複新增。
5. 測試兩個門店互不可見、0 目標、100% 以上達成率、其他平台名稱、跨月資料。
6. 經管理者同意後清除測試記錄，再通知夥伴使用。230 人規模正式啟用前，先以單店實測 Apps Script 配額與載入速度。
